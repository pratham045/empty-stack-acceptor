Algorithm
  1. Start with an empty stack.
  2. Read the input string from left to right.
  3. For every "a", push "A" onto the stack.
  4. When the first "b" appears, move to the popping phase.
  5. For every "b", pop one "A".
  6. If the stack is empty before all b's are processed, reject.
  7. If an "a" occurs after a "b", reject.
  8. After processing the complete string, inspect the stack.
  9. If the stack is empty, accept.
  10. Otherwise, reject.
Pseudocode
START
stack = empty
phase = "a"
FOR each character ch in input:
  IF ch == 'a':
    IF phase == "b": REJECT
    PUSH 'A'
  ELSE IF ch == 'b':
    phase = "b"
    IF stack is empty: REJECT
    POP 'A'
  ELSE: REJECT
IF input finished AND stack empty: ACCEPT
ELSE: REJECT
END
Why is this called an Empty Stack Acceptor?

A Pushdown Automaton can accept a string when its stack becomes empty after the complete input has been processed. The stack temporarily stores information about previously read symbols. Here every "a" pushes one symbol and every "b" removes one. If all pushed symbols are matched and removed exactly when the input finishes, the string is accepted.

Formal PDA definition
M = (Q, Σ, Γ, δ, q0, Z0, F)
Q = {q0, q1, q_accept, q_reject}
Σ = {a, b}     Γ = {A, Z0}
q0 = start state, Z0 = initial stack symbol
F = ∅  (acceptance by empty stack, language N(M))

δ(q0, a, Z0) = {(q0, A Z0)}
δ(q0, a, A)  = {(q0, A A)}
δ(q0, b, A)  = {(q1, ε)}
δ(q1, b, A)  = {(q1, ε)}
δ(q1, ε, Z0) = {(q_accept, ε)}

If "Each a pushes" is set to k, every "a" pushes k A's and the language becomes aⁿbᵏⁿ. Turn on "Textbook model (Z₀)" to watch Z₀ sit at the bottom and get popped by the final ε-move. With it off, the stack simply starts empty (simplified model).

Complexity

Time: O(n), because each input character is processed once.
Space: O(n), because in the worst case all "a" characters are stored in the stack.
